## Concrete follow-up corrections

The following are current source changes, not hypothetical recommendations:

1. **Library failure recovery:** a rejected catalogue request now produces an error and Retry. Retry invokes the existing store loader, and returning online triggers another attempt. The shared boolean `useCatalog` hook API was not changed. In the isolated browser check, the aborted catalogue request ended with an alert and zero skeletons; allowing the request and retrying produced 60 results with no remaining error. Locale copy was pending in that initial check; the subsequent targeted E2E passed with the final error/retry text.
2. **Measurement history:** replaces the silent ten-row cutoff with a visible shown/total count and ten-at-a-time Show more. The unit check covers a twelve-record initial render, ten delete controls and the disclosure action; it does not substitute for clicking through the final page.
3. **Calendar scope:** replaces the permanently disabled whole-month action with explicit scope text and a conditional clearing action, including focus restoration. The targeted reset-focus E2E subsequently passed.
4. **Exercise progress:** preserves the requested exercise even without completed history, communicates that state and retains the picker.
5. **Training actions:** adds pending/error handling to routine/program/template sheet mutations, keeps retry IDs stable and avoids late navigation after leaving the screen. Workout-detail repeat becomes an explicit resume action when another session exists. Train pending/retry was browser-confirmed; the existing-session E2E passed without creating an extra routine.
6. **Plan import:** ignores navigation feedback from a completed import after the user has left that route.

7. **Workout editing and domain validation:** invalid dates/times, zero or negative workout duration, invalid set values and non-finite totals are rejected before persistence, with specific visible validation messages. Saving locks draft controls and prevents duplicate submissions; failure retains the draft for retry, and a completion after leaving the route does not navigate back unexpectedly. The gym reviewer browser-confirmed zero-duration and negative-weight rejection, retry after failure, pending controls and stale-navigation behavior.

The calendar, training, progress and import diffs were independently source-reviewed here; the editing/domain diff was also inspected for this update. Completed targeted team checks are identified above. The final frozen-source run passed all 118 E2E scenarios.

## Independent History.tsx review

No blocking defect was found in the calendar follow-up change. The selected-day query is scoped to the calendar element, so it cannot accidentally focus a pressed control elsewhere. Focus moves before the clear button unmounts, and clearing the day resets pagination without changing the month. Day toggling and month navigation retain their existing reset behavior. The status text makes the result scope visible even when the reset action is absent.

“Show whole month” continues to respect the visible text/routine/exercise filters. It clears the day restriction, not every filter. This is consistent with the implementation; the report does not describe it as showing all unfiltered workouts. The root subsequently reports a passing reset-focus E2E and eight calendar captures across 320/390 px, Italian dark and English light, with no horizontal overflow or JavaScript errors. The root visually inspected two of those captures. This is team-reported browser evidence; no screen-reader result is claimed.
