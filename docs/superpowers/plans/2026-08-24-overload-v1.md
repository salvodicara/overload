# Overload v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Overload PWA v1: full workout core (routines, logging with progression suggestions and headphone-audible rest timer, history, charts, exercise library with media, import/export) with Google login and Firestore sync, deployed on Firebase Hosting.

**Architecture:** Local-first PWA — Dexie/IndexedDB is the on-device source of truth; a thin LWW sync layer mirrors records to Firestore per user. Pure-logic modules (progression, CSV parsing, merge, volume/PR) are framework-free and TDD'd; React screens consume them via a Zustand store.

**Tech Stack:** Vite, React 18, TypeScript (strict), Zustand, Dexie, i18next, vite-plugin-pwa, Firebase JS SDK (auth+firestore), Vitest (+fake-indexeddb), Playwright.

**Spec:** `docs/superpowers/specs/2026-08-24-overload-design.md`

## Global Constraints

- TypeScript `strict: true`; no `any` in committed code.
- ZERO hardcoded user-facing strings: every string via i18next keys in `src/i18n/it.json` + `src/i18n/en.json` (both files updated in the same commit that adds a key).
- Weights in kg (number), dates as `YYYY-MM-DD` strings, timestamps as epoch ms.
- Every synced record carries `id: string` and `updatedAt: number`.
- No personal workout data in the repo (`data/personal/` is gitignored).
- Dependencies: only those listed in Tech Stack (ponytail rule — justify any addition in the commit message).
- Copy Hevy/StrengthLog UX freely; never their assets, media, or copy.
- Commit after every green test cycle; conventional commit messages.

// types.ts
export type SetLog = { exerciseId: string; weightKg: number; reps: number; done: boolean; isPr?: boolean };
export type Workout = { id: string; routineId?: string; dayLabel?: string; date: string; startTs: number; endTs?: number; sets: SetLog[]; volumeKg: number; note?: string; updatedAt: number; source: 'app' | 'hevy' | 'import' };

### Task 4: Phase + progression engine

**Files:** Create `src/lib/progression.ts`, `src/lib/__tests__/progression.test.ts`

**Interfaces:**

```ts
export type Phase = { week: number; key: 'reactivation' | 'rebuild' | 'progress' | 'deload' | 'done' };
export function getPhase(programStartDate: string | undefined, today: string): Phase | null; // weeks 1-2,3-5,6-8,9,>9
export type Suggestion = { weights: number[]; hintKey: string };
export function suggest(rx: RoutineExercise, history: Workout[], phase: Phase | null): Suggestion;
```

Rules (TDD each): no history → all sets `startWeightKg ?? 0`, hint `suggest.start`. History exists → per-set weights from the most recent workout containing done sets of that exercise; if that workout closed the top of the rep range (`repMax` reps on ≥ `rx.sets` done sets) → add `incrementKg ?? 2.5` to every set, hint `suggest.increase`; else hint `suggest.repeat`. Phase `reactivation` AND exercise never logged in-app → force `startWeightKg`, hint `suggest.phase1`. Phase `deload` → last weights × 0.6 rounded to 2.5, hint `suggest.deload`.

- [ ] Write the failing tests for all five rules with literal fixture workouts; run (FAIL); implement; run (PASS); commit `feat: progression engine`

### Task 9: Sync core (pure LWW) + Firestore adapter

**Files:** Create `src/lib/sync.ts`, `src/lib/__tests__/sync.test.ts`

**Interfaces:** Pure: `type Synced = { id: string; updatedAt: number }`; `diffForSync<T extends Synced>(local: T[], remote: T[]): { push: T[]; pull: T[] }` — newer `updatedAt` wins per id; missing on one side goes to the other. Adapter (not unit-tested; exercised via e2e/manual): `startSync(uid)` — on login, connectivity regain, visibilitychange and after every local write: pull remote collections (`users/{uid}/workouts|routines|settings`), run `diffForSync`, write pulls to Dexie, push with `setDoc`.
